# أذكار الصباح والمساء

تطبيق ويب شخصي لمتابعة أذكار الصباح والمساء، بعدّاد لكل ذكر وحفظ تلقائي للتقدم في المتصفح. المشروع مخصص لجهاز واحد، ولا يوجد تسجيل دخول ولا مزامنة بين الأجهزة. التقدم والإعدادات محفوظة محلياً بصيغة JSON في `localStorage`، والتطبيق لا يحتاج خادماً ولا تثبيتاً.

## الميزات

- **الأقسام**: ١٦ ذكراً في الصباح، و١٩ في المساء، و٥ أذكار استيقاظ مكمّلة للصباح، و١٠ أذكار نوم مكمّلة للمساء.
- **عدّاد لكل ذكر**: زر واحد يزيد العدد حتى يكتمل، مع شريط تقدم للقسم.
- **أذكار الاستيقاظ المكمّلة**: تُعرض في نهاية الصباح بعدّادها وشريط تقدمها، ولا تُحتسب في اكتمال الصباح ولا في «اليوم كامل» ولا في السلسلة. إكمالها كلها — حتى لو لم تكتمل بقية أذكار الصباح — يحوّل نقطة الصباح في تقويم ذلك اليوم إلى ذهبية.
- **أذكار النوم المكمّلة**: لها عدّادها وشريط تقدمها، ولا تُحتسب في اكتمال المساء ولا في «اليوم كامل» ولا في السلسلة. إكمالها كلها — حتى لو لم تكتمل بقية أذكار المساء — يحوّل نقطة المساء في تقويم ذلك اليوم إلى ذهبية.
- **عدّاد كبير**: نافذة للعدّ بضغطات كبيرة للأذكار المتكررة، مع تأكيد قبل إعادة العدّ.
- **اختيار تلقائي للقسم**: الصباح من ٠٤:٠٠ إلى ١٥:٠٠، والمساء فيما عدا ذلك.
- **حفظ يومي**: يُخزَّن التقدم تحت تاريخ اليوم، ويُحتفظ بآخر ٦٠ يوماً.
- **السلسلة والملخص**: السلسلة الحالية وأفضلها، وملخص آخر ٧ أيام (أيام كاملة، صباح، مساء).
- **تقويم شهري**: نقاط لكل يوم توضح اكتمال الصباح والمساء، وتصبح النقطة ذهبية عند إكمال مجموعة الاستيقاظ أو النوم، مع تفصيل عند اختيار اليوم. اختيار يوم سابق يعرض أذكاره في الأعلى ليقرأها ويعدّلها، مع شريط يوضح اليوم المعروض وزر «عرض اليوم» للعودة؛ والتعديل يُحفظ لذلك اليوم لا لليوم الحالي.
- **الوقت المتبقي**: يظهر تحت وصف الوقت، ويتحدّث كل ٣٠ ثانية، ويُخفى عند عرض يوم سابق.
- **زر «التالي»**: يعرض عدد الأذكار المتبقية وينتقل لأول ذكر غير مكتمل ويبرزه.
- **عنوان التبويب**: يعرض عدد الأذكار المتبقية في القسم النشط، ويصبح ✓ عند الاكتمال.
- **السحب الأفقي**: يساراً إلى المساء، ويميناً إلى الصباح.
- **التراجع**: شريط سفلي لمدة ٥ ثوانٍ يعيد آخر خطوة فقط، مع بقاء زر «إعادة» لكل ذكر.
- **حجم الخط**: أربعة مستويات لنصوص الأذكار فقط.
- **الألوان**: تلقائي يتبع القسم النشط، أو حسب الوقت، أو صباح/مساء بشكل يدوي ثابت.
- **نسخ احتياطي JSON**: تصدير واستيراد مع معاينة وخياري الدمج أو الاستبدال، ونافذة تأكيد بعد كل عملية.
- **تصدير CSV**: ملخص يومي لفروق الصباح والمساء والمجموعتين المكمّلتين، مناسب لجداول البيانات.
- **تذكير بالنسخ الاحتياطي**: ينبّهك إذا مرّ ١٤ يوماً دون تصدير نسخة.
- **تذييل الصفحة**: بطاقتا GitHub وInstagram بأيقونتاهما، وسطر الإصدار والسنة، واسم المطوّر. قيم التذييل محفوظة مرة واحدة في `app/config.js` داخل `appMeta`.
- **خطوط محلية**: خطوط التطبيق داخل المشروع، فلا يعتمد على مكتبات أو خطوط خارجية.
- **إتاحة**: واجهة عربية RTL، تسميات لقارئ الشاشة، وإعادة تعيين اليوم بخطوتين.

## التشغيل

لا يحتاج المشروع إلى تثبيت أو بناء:

1. **الاستخدام المعتاد**: افتح نسخة GitHub Pages على `https://jabar-reda.github.io/adkar/`.
2. **محلياً**: شغّل خادماً بسيطاً من مجلد المشروع:

```bash
python -m http.server 8000
```

ثم افتح `http://localhost:8000`.

> لا يمكن فتح `index.html` مباشرةً عبر بروتوكول `file://`، لأن التطبيق يُحمَّل كوحدة ES (`<script type="module">`) والمتصفحات تمنع تحميل الوحدات من نظام الملفات؛ شغّل خادماً محلياً كما في الخطوة السابقة.

> التقدم محفوظ في `localStorage` الخاص بالمتصفح كـ JSON. مسح بيانات الموقع أو استخدام وضع التصفح الخاص يعني فقدان التقدم، لذا صدّر نسخة احتياطية بين فترة وأخرى.

## البيانات والتخزين

يُفصل التقدم عن الإعدادات في مفتاحين مستقلين:

| المفتاح | المحتوى |
|---|---|
| `adkar.v1` | التقدم اليومي، مع `schemaVersion` داخلي لترحيل البنية |
| `adkar.settings.v1` | حجم الخط والثيم وتاريخ آخر تصدير |

شكل بيانات التقدم:

```json
{
  "days": {
    "2026-10-31": {
      "morning": {
        "morning-ayat-al-kursi": { "count": 1, "done": true }
      },
      "evening": {},
      "wake": {
        "wake-wake-after-sleep": { "count": 1, "done": true }
      },
      "sleep": {
        "sleep-last-two-baqarah": { "count": 1, "done": true }
      }
    }
  },
  "stats": {
    "bestStreak": 0,
    "currentStreak": 0,
    "currentStreakDate": null
  }
}
```

- لكل ذكر `id` صريح وثابت مستقل عن عنوانه وترتيبه؛ مفتاح التخزين هو اسم القسم متبوعاً بالمعرّف، مثل `morning-ayat-al-kursi`. تُرحّل تلقائياً المفاتيح القديمة المعتمدة على الفهرس (`morning-0` ونحوها) ومفاتيح إصدار hash السابق إلى المعرّفات الصريحة.
- أذكار الاستيقاظ محفوظة في مجموعة `wake` مستقلة، وأذكار النوم في مجموعة `sleep` مستقلة، ولا تدخل أي منهما في حساب اكتمال قسمها.
- **يوم كامل** = اكتمال قسم الصباح وقسم المساء معاً. التقويم يميز اليوم الجزئي (قسم واحد) عن اليوم الكامل. المجموعتان المكمّلتان لا تشترطان لاكتمال اليوم.
- تُحفظ تفاصيل آخر ٦٠ يوماً عادةً. إذا كان اليوم قيد الإنجاز وكان الأمس مكتملاً، يُحتفظ مؤقتاً بيوم إضافي حتى لا ينقطع حساب السلسلة عند أول حفظ لليوم الجديد. تُحفظ «السلسلة الحالية» وتاريخ آخر يوم مكتمل و«أفضل سلسلة» كإحصاءات مستقلة؛ لذلك تستمر القيم بدقة بعد تقليم التفاصيل. النسخ القديمة لا تستطيع استعادة سلسلة تاريخية سبق حذف أيامها قبل هذا التحديث.
- البيانات محلية على هذا الجهاز فقط، ولا تُرسل إلى أي خادم.
- **التخزين حسب المنصة**: على المتصفح يُستخدم `localStorage`؛ في تطبيق Android (Capacitor) يُستخدم `@capacitor/preferences` (SharedPreferences/UserDefaults) لزيادة ديمومة البيانات، مع بقاء الإعدادات في `localStorage` (قراءة متزامنة قبل أول رسم). كل الوصول إلى التخزين يتم عبر `app/storage.js` (adapter)، فلا يعلم منطق التطبيق أي منصة يعمل عليها.
- **طلب التخزين الدائم (ويب)**: عند الإقلاع يطلب التطبيق من المتصفح تخزيناً دائماً عبر `navigator.storage.persist()` حيث تتوفر هذه الواجهة، فيقل احتمال مسح المتصفح للبيانات عند ضغط المساحة. الطلب لا يعطّل الواجهة؛ وإن رُفض أو لم تُدعم الواجهة يبقى التخزين عادياً دون أي تأثير آخر.
- **البنية**: قاعدة كود واحدة (`app/` و`index.html`) تعمل على الويب وAPK، بلا frameworks ولا bundler؛ طبقة التخزين هي التجريد الوحيد بين المنصتين.
- عند فتح التطبيق في أكثر من تبويب، تُحدَّث بقية التبويبات عند تغيّر التقدم أو الإعدادات. في المتصفحات التي تدعم Web Locks، تُسلسَل عملية قراءة الحالة ودمجها وكتابتها داخل قفل مشترك، مع دمج التعديلات المستقلة على مستوى الذكر قبل الكتابة؛ وهذا يمنع الكتابات القديمة المتزامنة بين نسخ التطبيق المتعاونة. في المتصفحات التي لا تدعم Web Locks يبقى الحفظ محلياً، ولا يمكن ضمان منع تعارض الكتابات لأن `localStorage` لا يوفر معاملات أو أقفالاً ذرية.
- إذا تعذّر الحفظ (مساحة ممتلئة أو تصفح خاص)، يظهر تحذير تحت شريط التقدم ويبقى التقدم في الذاكرة حتى إغلاق الصفحة.
- عند التحميل تُنظَّف البيانات في الذاكرة: تُقصّ العدادات، ويُعاد حساب الاكتمال، وتُهمل التواريخ غير الصالحة أو المستقبلية والمفاتيح غير المعروفة. تُرحّل البنية القديمة إلى `schemaVersion: 3` عند الحفظ التالي. الأيام المسجلة قبل إضافة سورة الملك إلى أذكار المساء (`schemaVersion: 2` أو أقدم) يُعدّ مساؤها مكتملاً بسورة الملك إذا اكتملت بقية أذكار المساء، أما إن كان للملك إدخال صريح — ولو بصفر — فيبقى كما هو. إذا كانت البيانات تالفة أو من إصدار أحدث، يتوقف الحفظ التلقائي ويظهر تحذير بدلاً من الكتابة فوقها؛ استعد البيانات باستيراد نسخة سليمة.

## النسخ الاحتياطي

- **التصدير**: من قسم «الإعدادات» ← «تصدير نسخة». يُنزّل ملفاً باسم `adkar-YYYY-MM-DD.json` يحتوي التقدم والإعدادات، ثم تظهر نافذة تأكيد بالنص الكامل للنسخة مع زر نسخ.
- **الاستيراد**: «استيراد نسخة» ← اختر الملف ← راجع المعاينة ← اختر «دمج مع الحالي» أو «استبدال الكل». تظهر بعدها نافذة تأكيد بالنتيجة.
- **لصق نسخة**: داخل تطبيق أندرويد لا يعمل اختيار الملفات ولا التنزيل المباشر في كل الأجهزة؛ زر «لصق نسخة» يفتح نافذة تُلصق فيها نص JSON كاملاً ثم «فحص النسخة» ليعرض نفس المعاينة. ويمكن أيضاً استخدام «نسخ النص» بعد التصدير لحفظ النسخة خارج التطبيق.
- **الدمج**: يحتفظ بالعدد الأكبر لكل ذكر (ولا يخفض أي عدّاد)، ويضم الأيام الجديدة، ويحتسب الذكر بلا عدد محدد مكتملاً إذا كان مكتملاً في أي من النسختين. لا يغيّر إعداداتك الحالية.
- **الاستبدال**: يمسح التقدم الحالي ويأخذ تقدم الملف وإعداداته بعد التأكيد.
- تُرفض الملفات الأكبر من ٢ ميجابايت، والتواريخ غير الصالحة، والتواريخ المستقبلية.
- نسخ احتياطية أقدم باسم `douaa-tracker-*.json` (من إصدار المشروع الأول) تُستورد وتُدمج بلا أي خطوة إضافية؛ الاستيراد يفحص البيانات لا اسم التطبيق في الملف.
- تُقصّ العدادات على الحد الأقصى لكل ذكر، ويُعاد حساب الاكتمال، ويُحتفظ بآخر ٦٠ يوماً فقط.
- **تذكير**: عند مرور ١٤ يوماً دون تصدير نسخة، يظهر تنبيه في الإعدادات.

### تصدير CSV

- زر «تصدير CSV» ينزّل ملخصاً يومياً باسم `adkar-YYYY-MM-DD.csv` على الويب؛ وداخل تطبيق أندرويد يعرض النص في نافذة تأكيد مع زر «نسخ النص» لأن تنزيل الملفات غير متاح في WebView.
- الأعمدة: التاريخ، اكتمال الصباح، عدد أذكار الصباح المكتملة، أذكار الاستيقاظ المكتملة، اكتمال المساء، عدد أذكار المساء المكتملة، أذكار النوم المكتملة، اكتمال اليوم.
- يُكتب الملف بترميز UTF-8 مع BOM، ويفتح في Excel بالعربية دون إعدادات إضافية.
- أذكار الاستيقاظ وأذكار النوم تُصدَّر كل منهما في عمود مستقل، ولا تؤثر في عمود «اكتمل اليوم».
- التواريخ في CSV ميلادية بصيغة `YYYY-MM-DD`، والأرقام لاتينية لتسهيل الفرز والحساب.

## الإعدادات

- **حجم نص الأذكار**: صغير، متوسط، كبير، كبير جداً.
- **الألوان**:
  - `تلقائي`: يتبع القسم النشط (صباح أو مساء).
  - `حسب الوقت`: يتبع الساعة نفسها بنفس نافذتي الصباح والمساء، ويتحدث تلقائياً.
  - `صباح` أو `مساء`: يثبّت اللوحة حتى عند تبديل القسم. لا يؤثر الثيم على تحديد القسم النشط.
- الإعدادات محفوظة لكل جهاز على حدة، ويُضاف إليها تاريخ آخر تصدير لتذكير النسخ الاحتياطي.

## الاختبارات

```bash
npm test
```

أو مباشرة:

```bash
node tests/tests.js
```

- `tests/tests.js`: ملف واحد يشغّل الفحوصات بالتتابع: فحص الصياغة والبنية والمعرّفات والأصول، ثم محاكاة DOM وسلوك التطبيق. يعيد رمز فشل إذا فشل أي فحص، ويشغّله GitHub Actions عند كل دفع أو طلب دمج.
- `tests/cross-tab-sync.html` مع `tests/browser-sync.spec.cjs`: اختبار تكاملي بمتصفّح Chromium يفتح نسختين مستقلتين من التطبيق، ويسجل تحديثين متزامنين ويتحقق من بقائهما معاً، كما يتحقق من استعادة لقطة التخزين السابقة. يشغّله سير عمل `Browser synchronization` في GitHub Actions؛ Playwright أداة اختبار CI فقط وليست اعتماداً للتطبيق.

## بناء تطبيق أندرويد

الموقع نفسه لا يُلمس في البناء؛ يُنسخ إلى `apk/www` ويُغلّف بـ Capacitor في WebView. مفتاح التوقيع **لا يُنشأ في CI** — أنشئه محلياً مرة واحدة وأضفه للأسرار.

1. **أنشئ مفتاح التوقيع محلياً** (مرة واحدة، واحفظه في مكان آمن — إن فقدته لا يمكنك تحديث التطبيق لاحقاً):
   ```powershell
   keytool -genkeypair -v -keystore adkar.keystore -alias adkar -keyalg RSA -keysize 2048 -validity 10000
   ```
2. **أضفه إلى أسرار المستودع** (Settings ← Secrets and variables ← Actions):
   - `ANDROID_KEYSTORE`: محتوى الملف بترميز base64.
   - `ANDROID_KEYSTORE_PASSWORD`: كلمة المرور التي أدخلتها.
   - PowerShell لترميز الملف:
     ```powershell
     [Convert]::ToBase64String([IO.File]::ReadAllBytes("adkar.keystore")) | Set-Clipboard
     ```
3. **احذف ملف `adkar.keystore` من جهازك** بعد نسخه إلى الأسرار (أو احتفظ به في مكان آمن، لا في المستودع).
4. لإصدار عام، اتبع خطوات [نشر إصدار على GitHub Releases](#نشر-إصدار-على-github-releases) وادفع الوسم `vMAJOR.MINOR.PATCH`. سيُبنى APK ويُنشر تلقائياً في صفحة Releases.
5. للبناء التجريبي فقط، افتح **Actions** ← **بناء ونشر APK** ← **Run workflow**، أدخل رقم الإصدار، ثم حمّل Artifact الناتج. هذا التشغيل اليدوي لا ينشئ Release عاماً.

- في الإصدارات المنشورة، يُشتق `versionName` من الوسم ويُحسب `versionCode` منه؛ لا تعِد استخدام رقم إصدار سابق.
- أيقونة التطبيق وشاشة البداية تولَّدان مسبقاً بـ `apk/make-icons.py`.
- المشروع المولّد `apk/android/` لا يُرفع إلى المستودع، وهو مستثنى في `.gitignore`.
- البناء **يفشل** (وليس ينشئ مفتاحاً) إذا كانت الأسرار غير مضبوطة — هذا مقصود لحماية مفتاح التوقيع.
- التحقق من التوقيع: `jarsigner -verify app-release.apk`.

## نشر إصدار على GitHub Releases

يُنشأ إصدار Android موقّع تلقائياً ويُنشر في صفحة [Releases](https://github.com/jabar-reda/adkar/releases) عند دفع وسم إصدار إلى GitHub.

### تجهيز مفاتيح التوقيع (مرة واحدة)

قبل أول نشر، أضف الأسرار التالية من Settings ← Secrets and variables ← Actions:

- `ANDROID_KEYSTORE`: ملف keystore كاملاً بترميز Base64.
- `ANDROID_KEYSTORE_PASSWORD`: كلمة مرور keystore.

أنشئ المفتاح محلياً مرة واحدة فقط، وفق الخطوات في قسم «بناء تطبيق أندرويد». **احتفظ بنسخة آمنة خارج جهاز البناء**؛ لا ترفع المفتاح أو كلمة مروره إلى GitHub أو إلى المستودع. يجب استعمال المفتاح نفسه في كل الإصدارات اللاحقة حتى يتمكن مستخدمو النسخة السابقة من تثبيت التحديث فوقها.

### نشر إصدار جديد (مثال v1.0.4)

التسلسل المتبع: أنشئ الإصدار (Release) على GitHub كمسودة، ثم ادفع الوسم من جهازك فيبني السير عمل APK ويرفعه إلى المسودة، وأخيراً تنشرها.

1. بعد التأكد من إعداد الأسرار ونجاح الاختبارات على `main`، افتح صفحة [Releases](https://github.com/jabar-reda/adkar/releases) ← **Draft a new release**:
   - **الوسم**: `v1.0.4`. المسودة لا تنشئ الوسم فعلياً حتى نشرها، فلا يتعارض دفعه لاحقاً.
   - **العنوان**: `Adkar v1.0.4` — اكتبه مطابقاً للوسم حرفياً؛ العنوان يدخل يدوياً فاحثّ أخطاء النسخ.
   - اكتب ملاحظات الإصدار ثم احفظ **Draft** دون نشر.
2. من جهازك ادفع الوسم ليبدأ البناء:
   ```bash
   git checkout main
   git pull origin main
   git tag -a v1.0.4 -m "Adkar v1.0.4"
   git push origin v1.0.4
   ```
3. يتحقق سير عمل **بناء ونشر APK** من رقم الإصدار، ويبني APK باستخدام Capacitor وAndroid، ويتحقق من توقيعه، ثم يرفع إلى الإصدار القائم بهذا الوسم:
   - `adkar-v1.0.4.apk`: ملف التثبيت.
   - `adkar-v1.0.4.apk.sha256`: بصمة SHA-256 للتحقق من سلامة الملف.
   إذا وُجد ملف بالاسم نفسه في الإصدار فسيُستبدل بالنسخة الجديدة.
4. راجع نتيجة التشغيل في تبويب **Actions**، ثم انشر المسودة من صفحة الإصدار.

إن لم يوجد أي إصدار بهذا الوسم عند انتهاء البناء، ينشئ السير عمل الإصدار تلقائياً بعنوان `Adkar v1.0.4` مع ملاحظات مولدة من الوسم.

### قواعد الإصدارات التالية

- استخدم وسوماً بصيغة `vMAJOR.MINOR.PATCH` (الإصدار الدلالي):
  - `PATCH` — الرقم الثالث: إصلاحات بسيطة لا تغيّر ميزة، مثل `v1.0.4` بعد `v1.0.3`.
  - `MINOR` — الرقم الثاني: ميزة جديدة كاملة، أو إعادة كتابة ملف كامل، مثل `v1.1.0`.
  - `MAJOR` — الرقم الأول: تغيير جذري كبير في التطبيق، مثل `v2.0.0`.
- لا تعِد استخدام وسم سبق نشره، ولا تغيّر محتواه بعد النشر.
- يُشتق `versionName` من الوسم، ويُحسب `versionCode` منه بصيغة رقمية متزايدة؛ لذلك يجب أن تكون أرقام الإصدارات أعلى من الإصدار السابق.
- تشغيل سير العمل يدوياً من Actions يبني APK تجريبياً ويرفعه كـ Artifact لمدة 30 يوماً، لكنه **لا ينشئ Release عاماً**.
- لا تحذف keystore القديم ولا تنشئ مفتاحاً جديداً عند كل إصدار. فقدان المفتاح يمنع تحديث التطبيق المثبت بالمفتاح السابق.

> ملاحظة الترخيص: المستودع يصف المشروع بأنه خاص وجميع الحقوق محفوظة. نشر ملف APK يتيح تنزيله، لكنه لا يحوّل الشيفرة إلى مشروع مفتوح المصدر ولا يمنح تلقائياً حقوق إعادة التوزيع أو التعديل.

## الخصوصية

- لا حسابات، ولا تحليلات، ولا خادم، ولا إرسال لبيانات التقدم.
- كل البيانات في `localStorage` على جهازك.
- الخطوط والأيقونات محلية، فلا يطلب التطبيق أي ملف من خارج موقعه.

## ملاحظات للتطوير

- وزّع التعديلات على الملف المناسب: البنية في `index.html`، والتنسيق في `app/styles.css`، والمنطق في `app/app.js`، ونصوص الأذكار وقوائمها في `app/data.js`، وتهيئة الثيم قبل الرسم في `app/theme-init.js`. لا يوجد `npm install` ولا bundler.
- شغّل `npm test` بعد أي تعديل قبل الكوميت.
- لا تُعِد تحميل الخطوط من Google Fonts؛ ملفات `app/fonts/` محلية، وتبقى ملفات الترخيص بجانبها.
- لكل ذكر معرّف صريح في بياناته؛ لا تستخدم العنوان أو الفهرس لتكوين الهوية. عند إضافة ذكر جديد، امنحه `id` فريداً وثابتاً، ولا تغيّر معرّف ذكر قائم. تقرأ طبقة الترحيل مفاتيح الفهرس القديمة ومفاتيح hash السابقة وتحفظها بالمعرّف الصريح. أذكار الاستيقاظ في مجموعة `wake` وأذكار النوم في مجموعة `sleep`.
- الثوابت المشتركة بين `app/theme-init.js` و`app/app.js` في `app/config.js`: مفاتيح التخزين، وأحجام الخط، والثيمات، ونوافذ الصباح والمساء. عدّلها هناك فقط. أما الثوابت الخاصة بالمنطق فتبقى في `app/app.js`: `KEEP_DAYS`، `BACKUP_REMINDER_DAYS`، و`MAX_BACKUP_BYTES`.
- `app/theme-init.js` يطبّق الثيم وحجم الخط قبل الرسم لمنع وميض الألوان؛ يقرأ القيم المشتركة من `app/config.js` المحمّل قبله. الثيم `time` يعتمد فيه هذا السكربت على الساعة مثل `auto`، ثم يُصحَّح بعد التحميل.
- التعليقات في الكود عربية وتشرح «لماذا» لا «ماذا»: ما يظهر من اسم الدالة أو القاعدة لا يحتاج تعليقاً، وما يحتاجه هو سبب القرار والحيلة غير البديهية. عند تعديل سلوكٍ علّق على سببه بجواره.
- رسائل الكوميت تتبع [Conventional Commits](https://www.conventionalcommits.org/): `feat:`، `fix:`، `docs:`، `chore:`.
